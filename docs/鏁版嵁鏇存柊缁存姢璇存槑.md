# 数据更新与维护说明

## 重要前提

这个系统出厂时**不包含任何编造的真实录取数据**。所有 `data/*.json` 里的院校/分数/位次都明确标注了 `isRealData: false`，且文字上写着"示例"。这是有意为之：

高考志愿填报数据涉及成千上万院校 × 专业 × 省份的具体数字，任何编造或记忆模糊的分数线，一旦被当真使用，可能直接影响一个学生的真实升学决策。所以这套系统把"真实数据从哪来、怎么核验"完全交给你，自己只负责把架构、算法、交互做扎实，并在数据导入时做格式与合理性校验。

---

## 一、当年数据从哪里获取

按可信度从高到低：

1. **省教育考试院官网**（最权威）——每年高考结束后，各省考试院会发布：
   - 一分一段表（通常6月下旬）
   - 各批次录取最低控制分数线（6月）
   - 招生计划合订本 / 报考指南（5-6月，含各校各专业组选科要求和计划数）
   - 录取结束后的"分专业录取最低分"（7-8月陆续公布，不是所有省份都公开到专业级别）

2. **阳光高考信息平台**（gaokao.chsi.com.cn）——教育部官方平台，可查院校历年在各省的录取数据，适合做历史趋势参考。

3. **院校本科招生网**——多数本科院校官网有"招生计划""录取分数线"专栏，部分公布到专业级别。

4. **省考试院官方APP/公众号**——部分省份当年数据会先在这些渠道推送，比官网更新。

⚠️ 避免使用：各类商业志愿填报APP/网站里二次转载的数据、往年论坛贴里手抄的数据——这些都可能有转录错误或滞后，建议只作为交叉核对的参考，不作为主数据源。

## 二、如何把数据录入系统

### 方式A：通过界面导入（适合小批量、临时补充）
1. 点击右上角「数据管理」
2. 把整理好的 JSON 数组粘贴进文本框
3. 点击「校验并导入」——系统会逐条检查字段完整性和数值合理性（如分数是否在0-750之间），不合格的条目会列出具体原因，不会被写入数据库
4. 导入成功后，列表和横幅计数会立即刷新

### 方式B：批量编辑 JSON 文件（适合一次性导入上百所院校）
1. 参考 `docs/数据导入模板.csv` 整理 Excel/CSV
2. 转换为 JSON（可以用 Excel 的"另存为"配合公式，或者写个几行的转换脚本）
3. 替换 `data/colleges.json` 和 `data/admission_plans.json` 中的对应数组
4. **关键**：每条记录把 `isRealData` 改成 `true`，系统据此判断这条数据是否可信，并会在横幅和卡片上去掉"示例数据"提示

### 方式C：一分一段表导入
`data/score_rank_tables.json` 目前 `table` 数组是空的。一分一段表数据量较大（通常每分一行，覆盖200-750分），建议：
1. 从省考试院官网下载当年一分一段表（通常是图片或PDF表格）
2. 转录为 `{score: 分数, cumulativeCount: 累计人数}` 的数组
3. 按物理类/历史类分别存成两条记录

在一分一段表为空时，系统的"分数→位次换算"功能会明确提示"暂无数据"，**不会编造换算结果**——这是有意的安全设计，请不要绕过它去填假数据。

## 三、新增省份

新高考3+1+2省份还包括：河北、辽宁、福建、湖北、湖南、江西、安徽、重庆等（以教育部当年公布的高考改革实施范围为准，请核实当年是否有新增/调整）。

新增方法：编辑 `data/provinces.json`，复制一个现有省份对象，改 `code`/`name`，并核对该省当年实际的：
- 批次设置（有些省份本科批/特殊类型批合并方式不同）
- 单批次志愿数量上限（不同省份不一样，且可能逐年调整）

## 四、每年的数据生命周期（建议流程）

```
当年6月：高考结束 → 一分一段表公布 → 更新 score_rank_tables.json
当年6-7月：各批次分数线/招生计划公布 → 更新 admission_plans.json，is_real_data 标 true
当年8月：录取结束，分专业实际录取分公布（部分省份）→ 补充/修正数据
次年同期：去年数据归档保留（year字段区分），新一年数据另起记录，方便系统未来支持"近3年对比"
```

系统当前默认按单一年份查询；如果你想恢复需求里提到的"近3年录取数据"展示，把 `admission_plans.json` 里同一院校同一专业组按不同 `year` 存多条记录即可，前端排序/筛选逻辑已经按 `year` 字段预留了索引（见 `db.js` 里 `byYear` index），扩展时无需改动数据库结构。

---

## 五、数据准确性的最终责任

这套系统提供的"冲稳保""位次换算"等都是基于你导入的数据做计算，计算逻辑本身已经过测试（见项目内的算法单元测试），但**结果的可信度完全取决于你导入数据的真实性**。建议：
- 至少两个独立来源交叉核对关键数字（最低分、最低位次）
- 优先信任省考试院官方发布的原始文件，而不是二次转载
- 录入后抽样核对几条，确认没有录错位/录错行的情况
- 任何用于真实填报决策的数据，最终都建议以当年官方公布的最新信息为准，系统只是辅助整理和计算工具
